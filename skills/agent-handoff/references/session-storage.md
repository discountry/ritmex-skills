# Native session and workspace assumptions

This skill deliberately keeps product-specific storage knowledge and Git snapshot logic inside `scripts/session_handoff.py`.

## Host detection

- Claude Code shell-tool subprocesses expose `CLAUDE_CODE_SESSION_ID`.
- Codex shell-tool subprocesses expose `CODEX_THREAD_ID`.
- If the Claude marker is absent, the workflow treats the host as non-Claude and reads Claude Code history, matching the skill's fixed handoff rule.

## Claude Code

Default root: `~/.claude`, overridden by `CLAUDE_CONFIG_DIR` when set.

Primary transcript pattern:

`<claude-root>/projects/<encoded-cwd>/<session-id>.jsonl`

Discovery first checks embedded `cwd` metadata. The encoded project-directory name is only a fallback when a transcript lacks embedded cwd metadata. The fallback encoding replaces each non-alphanumeric character in the absolute cwd with `-`.

The JSONL line schema is intentionally treated as semi-structured. The reader preserves raw lines and does not require a fixed message schema.

## Codex

Default root: `~/.codex`, overridden by `CODEX_HOME` when set.

Primary transcript pattern:

`<codex-root>/sessions/**/rollout-*.jsonl`

Discovery unions two sources:

1. newest readable `state_*.sqlite` `threads` metadata when available;
2. rollout JSONL `session_meta` / early metadata records.

The SQLite index is an optimization and metadata source. The rollout JSONL remains the transcript that is handed to the model. Archived threads are excluded from normal discovery.

## Completion detection

Native stores do not expose one portable, reliable `unfinished=true` field. The helper therefore owns deterministic exact-cwd filtering and newest-first ordering, and provides a conservative `status_hint` plus a tail preview. The model may skip a candidate only when the preview clearly shows completion. Ambiguous newest sessions remain preferred.

## Git workspace snapshot

The `workspace` subcommand owns live Git-state capture so the model does not infer changes from session history.

For a Git repository it emits one deterministic textual snapshot containing:

- canonical current working directory;
- canonical repository root;
- current branch, or `DETACHED`;
- exact HEAD commit;
- `git status --porcelain=v1 --branch --untracked-files=all`;
- complete unstaged `git diff --no-ext-diff --no-textconv --no-color --submodule=diff --`;
- complete staged `git diff --cached --no-ext-diff --no-textconv --no-color --submodule=diff --`.

Git commands run with pagers and color disabled. External diff drivers and textconv are disabled for the diff payload so the snapshot is generated by Git itself and is less dependent on local presentation configuration.

Untracked file paths are represented by porcelain status. Their contents are not synthesized into a fake Git diff; the agent may inspect an untracked file directly only when the unfinished task requires it.

Large snapshots are read in chunks. Every chunk regenerates the snapshot and returns its SHA-256. Later chunks must pass the first SHA-256 back through `--expect-sha256`; a mismatch aborts the handoff rather than allowing the model to combine different Git states.

Outside a Git repository, the helper returns a deterministic `git_repo=false` snapshot and the workflow continues from live files.

## Safety properties

- Session stores are read-only.
- Read chunks are addressed by discovered session ID, not arbitrary user paths.
- Each transcript chunk returns the full transcript SHA-256.
- Subsequent transcript chunks can require the same SHA-256 to prevent mixing a transcript that changed during handoff.
- Workspace chunks return a SHA-256 over branch metadata, status, unstaged diff, and staged diff.
- Subsequent workspace chunks can require the same SHA-256 to prevent mixing Git states.
- The helper never creates project metadata, branches, worktrees, commits, stashes, or session files.
